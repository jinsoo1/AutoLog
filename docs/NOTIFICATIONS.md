# 알림 정리

알림은 **한 번 잘못 만들면 사용자가 통째로 꺼버리는** 기능입니다.
어떤 알림이 언제 켜지고, 권한을 언제 묻고, 무엇이 얼마나 자주 울리는지 한곳에 모읍니다.

기준 시점: 1.3.0 개발 중 (1.2.2 배포 이후)

---

## 한눈에

| 알림 | 기본값 | 권한 묻는 시점 | 주기 | 채널 |
|---|---|---|---|---|
| 주간 주행거리 | **꺼짐** | 설정에서 켤 때 | 매주 일요일 20시 | `weekly_mileage_channel` |
| 정비 임박 | **꺼짐** | 설정에서 켤 때 | 매일 지정 시각(기본 9시) | `maintenance_soon_channel` |
| 정비 초과 | **꺼짐** | 〃 | 〃 | `maintenance_overdue_channel` |
| 날짜 일정 | **켜짐** | **첫 일정을 등록할 때** | 매일(같은 워커에 편승) | `schedule_channel` |
| 월간 리포트 | **켜짐** | **리포트 탭에 볼 데이터가 생겼을 때** | 매월 1일 9시 | `monthly_report_channel` |

**앱을 설치하자마자 권한을 묻지 않습니다.** 아직 아무 가치도 보여주지 않은 상태에서 묻는 건
거부당하기 가장 좋은 방법이고, 한 번 거부되면 다시 묻기 어렵습니다.

---

## 설치 직후 상태

신규 설치에서는 **알림 권한이 없고, 알림 채널도 없고, 일일 워커도 예약되지 않습니다.**

- 기본 켜짐인 두 알림(일정·리포트)은 "켜져 있지만 잠들어 있는" 상태입니다.
- 채널은 필요한 순간에 만듭니다 — Android 8+ 에서 채널 없이 보낸 알림은 **조용히 실패**합니다.
- 워커는 보낼 것이 생겼을 때 예약합니다. 매일 돌면서 아무 일도 안 하는 워커는 배터리만 씁니다.

### 깨어나는 지점

| 사용자 행동 | 그때 일어나는 일 |
|---|---|
| 설정에서 주간/정비 알림 ON | 권한 요청 → 채널 생성 → 해당 체인 예약 |
| **첫 날짜 일정 등록** | 권한 요청 → 채널 생성 → 일일 체인 예약 |
| **리포트 탭에 데이터가 찬 뒤 처음 열람** | 권한 요청(월간 리포트용, 1회만) |
| 앱 재실행 | 켜져 있고 대상이 있는 알림의 체인만 복구(KEEP — 살아 있으면 안 건드림) |

권한을 거부해도 기능은 죽지 않습니다. 일정은 저장되고 화면에서 D-day 로 볼 수 있고,
정비 상태도 홈·리포트에서 그대로 보입니다. 알림만 나가지 않을 뿐입니다.

## 알림별 규칙

### 주간 주행거리 (기본 꺼짐)
매주 일요일 20시, **이번 주에 주행거리를 갱신하지 않은 차량**이 있을 때만.

### 정비 임박·초과 (기본 꺼짐)
매일 지정 시각(기본 9시). 임박/초과를 따로 켜고 끌 수 있습니다.

- **상태가 바뀔 때만** 보냅니다(정상→임박 1회, 임박→초과 1회). 같은 상태로 머무는 동안은 침묵.
- 초과 리마인드를 켜면 초과 지속 중 7·14일마다 다시 알립니다(기본: 안 함).
- **기록이 없는 항목은 제외** — 0km·오늘 기준 계산이라 켜자마자 전부 초과로 뜹니다.
- 차량당 알림 1건으로 묶습니다(여러 항목이면 목록).

### 날짜 일정 (기본 켜짐)
정비 알림과 **같은 하루 1회 워커에 얹혀** 돕니다. 체인을 늘리면 끊길 자리도 늘어납니다.

- 단계: **2주 전 → 1주 전 → 당일 → 지남**. 단계가 넘어갈 때만 보내므로 일정당 최대 4번입니다.
- 날짜를 미뤄 되돌아가는 전이는 알리지 않습니다 — 사용자가 방금 직접 바꿨으니까요.
- **정비 알림 스위치와 별개**입니다. 정비 알림을 꺼둔 사람도 과태료가 걸린 정기검사는 받아야 합니다.
- 일정마다 개별 알림입니다(정비처럼 묶지 않음) — 각각이 별개 행동이라서.
- 완료 처리로 다음 회차로 넘어가면 단계 기록도 지워, 다음에 다시 2주 전부터 셉니다.

### 월간 리포트 (기본 켜짐)
매월 1일 9시, 지난달 지출 요약. 기록이 없는 달은 **조용히 넘어갑니다**(0원 리포트는 소음).

권한은 **리포트 탭에 보여줄 데이터가 있을 때 처음 열람하는 순간** 묻습니다.
설치 직후가 아니라 "이 사람에게 월간 리포트가 실제로 쓸모 있어진 시점"이라야
승낙받을 확률이 높고, 빈 리포트를 보는 사람에게 묻는 건 이릅니다.
결과와 무관하게 **한 번만** 묻습니다 — 거부 후 다시 물으면 시스템이 무시하고 사용자만 성가십니다.
거부해도 리포트 화면은 그대로 동작합니다.

## 반복하지 말아야 할 실수

이 세 가지는 **모두 "설정은 켜져 있는데 알림이 안 온다"로 나타납니다.** 사용자는 원인을 알 수 없고,
버그 리포트도 오지 않습니다. 조용히 실패하는 종류라 코드를 읽어야만 발견됩니다.

1. **워커 안에서 자기 자신을 KEEP 으로 재예약** — 실행 중인 자신 때문에 무시되어 체인이 끊깁니다.
   `APPEND_OR_REPLACE` 를 쓸 것. (1.2.2 에서 정비·주간 알림에 발생)
2. **재예약보다 먼저 return** — 조건 분기에서 빠져나가면 내일이 없습니다.
   재예약은 **모든 조건 검사보다 먼저**, 또는 하나라도 살아 있으면 걸어야 합니다.
3. **채널 없이 알림 발송** — Android 8+ 에서 조용히 실패합니다. 켤 때 반드시 `createChannels`.

그리고 **알림 기능은 실기기에서만 검증됩니다.** 유닛 테스트는 판정 규칙만 지켜주고,
체인이 실제로 이어지는지는 `dumpsys jobscheduler` 와 WorkManager 진단으로만 확인할 수 있습니다.

```
adb shell am broadcast -a "androidx.work.diagnostics.REQUEST_DIAGNOSTICS" -p <패키지>
adb logcat -d | grep WM-DiagnosticsWrkr     # 예약된 워커 목록
adb shell cmd jobscheduler run -f <패키지> <잡ID>   # 강제 실행
```
