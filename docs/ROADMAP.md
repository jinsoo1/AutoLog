# 기능 로드맵

버전별로 **무엇을 왜 그 순서로** 만드는지 적어둔 문서입니다.
아이디어 목록이 아니라 결정 기록이에요 — 같은 고민을 두 번 하지 않기 위해 이유를 함께 남깁니다.

기준 시점: **1.2.2 배포**(2026-08-18, versionCode 14)

---

## 관통 원칙

만들지 말지 헷갈릴 때 여기로 돌아옵니다.

1. **서버 없이.** 회원가입·로그인 없음이 이 앱의 정체성입니다. 서버가 필요한 기능은 하지 않거나, 서버 없이 되는 만큼만 합니다.
2. **기존 인프라부터 재사용.** 알림 체인 · 리포트 집계 · 백업 포맷 · 위젯. 새 인프라를 세우는 기능은 그만한 값을 해야 합니다.
3. **숫자를 지어내지 않습니다.** 계산할 수 없으면 `-`로 두고 이유를 밝힙니다. 이 원칙이 리포트·주행거리 제안 곳곳에 이미 박혀 있습니다.
4. **콘텐츠가 필요한 기능은 콘텐츠가 병목입니다.** 코드는 하루, 문구는 일주일. 항목 수를 줄여서 시작합니다.

## 가로지르는 자산: 정비 항목 지식 테이블

1.4.0 이후 기능 대부분이 **이 테이블 하나**에서 나옵니다. 따로 만들면 네 배 일이고, 한 번 만들면 네 기능이 열립니다.

| 열 | 예시 (엔진오일) | 쓰는 곳 |
|---|---|---|
| 함께 볼 항목 | 오일필터 · 에어클리너 | 정비소 모드 |
| 정비사에게 할 말 | "오일필터도 같이 봐주세요" | 정비소 모드 |
| 예상 작업 시간 | 30분~1시간 | 정비소 모드 |
| 계절 태그 | (없음) / 배터리=겨울 | 계절 관리 |
| 관련 증상 | (없음) / 브레이크패드=제동 시 소음 | 증상으로 찾기 |

**절반은 이미 있습니다.** `DefaultMaintenanceItems`에 30여 항목과 권장 주기가 들어 있어서, 새로 쓸 건 항목당 문구 몇 줄입니다.
다만 틀리면 신뢰를 잃는 종류라 **핵심 10개**로 시작해 반응을 보고 늘립니다.

**예상 비용은 테이블에 넣지 않습니다.** 전국 평균은 차종·지역에 따라 틀리고 물가 따라 낡습니다.
대신 **사용자 자신의 지난 기록**을 씁니다 — "지난번 8만원 (3월, OO카센터)". 정확하고, 로컬 전용 앱만 할 수 있는 답입니다.

## 1.3.0 — 날짜로 관리하기

주행거리로 안 잡히는 것들을 챙깁니다. **1.2.1·1.2.2 공지에서 두 번 예고한 기능**이라 약속을 지키는 릴리스이기도 합니다.
셋 다 날짜 기반이거나 기존 데이터만 쓰므로 인프라를 공유합니다.

### 날짜 기반 일정 ⭐ 예고함
- **자동차 정기검사** — 킬러 케이스. 비사업용 승용은 신차 4년 후 첫 검사, 이후 2년 주기라 **연식만 입력하면 자동 계산**됩니다. 놓치면 과태료라 알림 가치가 가장 크고 사용자 입력이 거의 없습니다.
- **보험 만기** — 갱신 시점 알림. 비교 견적을 볼 수 있어 실제로 돈이 되는 알림입니다.
- **자동차세** — 6월·12월(연납 1월) 고정이라 구현이 단순합니다.
- 리포트의 '다가오는 지출'에 자연스럽게 합류합니다.

### 계절별 관리
- 봄=에어컨 필터, 여름=냉각수·공기압, 장마=와이퍼, 겨울=배터리·부동액·타이어
- 단순 리마인더가 아니라 **"이번 겨울 전에 확인할 3가지"** 같은 콘텐츠형 알림으로.
- 날짜 일정과 트리거·알림 인프라가 같아서 **위 기능의 부록 수준 비용**입니다. 단독 릴리스감이 아님.
- 지금 만들면 첫 발송이 가을(겨울 대비) 시즌과 맞습니다.

### 리포트 — 정비 시기 예측
- 리포트가 이미 계산하는 **월평균 주행거리** + 항목별 남은 km → **"이 페이스면 11월쯤 엔진오일"**
- 거리 기준과 기간 기준 중 **먼저 오는 쪽**을 씁니다.
- 주행거리 관측점이 부족하면 계산하지 않고 **"주행거리를 업데이트하면 예상 시기를 알려드릴 수 있어요"** — 원칙 3과 맞고, 주행거리 입력을 유도하는 장치가 됩니다.
- 새 데이터도 콘텐츠도 필요 없는 **유일한 기능**이라 비용 대비 가치가 가장 좋습니다.

### 빈 상태 규칙 (기록이 없는 사용자)

차량을 등록하면 관리 스타일에 따라 **항목과 주기는 채워지지만 기록은 0건**입니다. 이게 신규 사용자의 기본 상태라, 세 기능 모두 이 상태에서 화면이 비지 않아야 합니다.

기준은 이미 앱 전체에 있는 `hasHistory` 규칙입니다 — 기록이 없는 항목은 0km·오늘 기준으로 계산돼 즉시 초과로 보이므로, 홈·리포트·알림·위젯에서 모두 제외합니다.

| 기능 | 기록이 없을 때 |
|---|---|
| 리포트 예측 | 계산하지 않고 **사유를 나눠서** 안내. 주행거리가 부족하면 "주행거리를 업데이트하면", 정비 기록이 없으면 "첫 정비 기록을 남기면" — 사유가 다르면 다음 행동도 다르다. 이때 '다가오는 지출' 카드도 같은 필터로 함께 비므로 섹션째 숨긴다. |
| 날짜 일정 | **정비 기록과 무관하게 100% 동작한다.** 연식·보험 만기·자동차세만 있으면 되므로, 기록이 0건인 신규 사용자에게 **즉시 가치를 주는 유일한 기능**이다. 차 등록 직후 "정기검사는 2027년 3월이에요"를 보여줄 수 있어 온보딩 축으로 쓴다. |
| 계절별 관리 | 카드를 **숨기지 않는다** — "무엇을 봐야 하나"라는 콘텐츠 자체가 기록과 무관한 가치다. 항목의 "마지막 2년 전"만 "아직 기록 없음"으로 바뀌고, 부제를 "지금 확인하고 기록해두면 다음부터 알려드릴 수 있어요"로. 각 줄의 기록 버튼이 곧 입력 경로가 된다. |

기록이 없을 때 리포트 예측과 계절 카드는 **기록을 유도하는 장치로 바뀝니다** — 빈 화면을 사과하는 대신 다음 행동을 줍니다. 정비 탭의 "기록 없는 항목" 흐름(1.2.x)을 그대로 재사용하면 새로 설계할 게 없습니다.

### 함께 정리
- 위젯 일일 갱신 워커가 `REPLACE`로 자기 자신을 취소하는 문제 (1.2.2에서 고친 알림 체인과 같은 계열)

## 1.4.0 — 정비소에서 쓰는 앱

차알못에게는 **주기 알림보다 체감 가치가 클 수 있는** 영역입니다. 정비소에서 말을 못 꺼내는 게 진짜 페인포인트예요.
지식 테이블 v1(10개 항목)을 만들고, 그 위에 두 화면을 올립니다.

### 정비소 가기 전 모드
- 이번에 확인할 항목 (앱의 임박·초과 데이터)
- 정비사에게 할 말 — "엔진오일 교환하러 왔어요. 오일필터와 에어클리너 상태도 같이 봐주세요."
- 예상 작업 시간
- 예상 비용 = **내 지난 기록** (없으면 줄 자체를 뺌)

### 정비 권유 판단
- "미션오일 갈라는데 해야 하나요?" — 현재 주행거리 · 마지막 교환 · 권장 기준을 비교해 **"교체 시기가 가까워요 / 여유가 있어 보여요"**
- 판단에 필요한 세 요소가 전부 앱에 이미 있습니다.
- 기록이 없는 항목이면 "언제 하셨어요?"를 묻게 되는데 **그 대답이 곧 기록 입력**입니다. 사용자가 가장 불안한 순간(돈 쓰기 직전)에 기록을 받아내는 구조라 앱 데이터도 좋아집니다.
- 문구에 **"참고용이며 최종 판단은 정비사와 상의하세요"**를 반드시 답니다.

## 1.5.0 — 증상으로 찾기

"브레이크 밟을 때 소리가 나요" / "시동이 한 번에 안 걸려요" / "핸들이 떨려요" / "차 밑에 액체가 떨어져요"

**여섯 아이디어 중 책임이 가장 큰 기능**이라 지식 테이블이 1.4.0에서 검증된 뒤에 갑니다. 설계 제약을 코드가 아니라 기획에 박아둡니다:

- 확정 진단을 하지 않습니다. **관련 가능성 항목 + 위험도 + 운행 가능 여부**까지만.
- **안전 직결 증상(브레이크·조향·누유)은 무조건 "가급적 빨리 점검 받으세요"** — 앱이 "괜찮다"고 말하는 선택지 자체를 만들지 않습니다.
- 앱의 차별점은 진단이 아니라 **내 기록과의 연결**입니다: "핸들 떨림 → 관련 항목: 타이어·휠 밸런스 → **타이어 교체하신 지 4년 됐네요**". 검색은 이걸 못 합니다.

## 프리미엄 묶음 (수익화)

**"보는 건 무료, 꺼내가는 건 유료"** — 리포트·알림 같은 핵심 기능은 절대 게이팅하지 않습니다.

- 영수증 사진 (주유·세차·정비·수리 전부)
- **이미지 포함 백업(ZIP)** — 사진 없는 반쪽 첨부는 하지 않습니다. 로컬 전용 앱에서 "백업에 사진 미포함"은 앱의 핵심 약속과 모순입니다.
- 증빙 리포트 내보내기 (PDF/엑셀) — 차곡차곡이 같은 걸 Premium으로 파는 것 확인 = 검증됨
- 로컬 전용 정체성상 **구독보다 1회 구매**. 리워드 광고는 게이트가 아니라 **결제 대안**(내보내기 1회 = 광고 1회 시청).
- `fuel_records.photoPath` 컬럼은 이미 있음(비어 있어 무해). 정비 쪽은 컬럼 추가 필요.
- ⚠️ 앱에 광고를 넣는 순간 `listing.md`·`promo.md`의 "광고 없다" 문구를 지울 것.

## 별도 트랙: 주차 위치 알림

정비 기록 라인과 무관해서 어느 버전에나 얹을 수 있습니다. **기술 검증이 먼저**입니다.

**흐름**: 차 연결 끊김(주차) 감지 → 알림 "어디에 주차하셨어요?" → **상단바에서 바로 입력**(RemoteInput) → 온고잉 알림으로 "🅿️ 지하 2층 B14" 유지 → 다음에 차가 연결되면 자동 제거(+ 수동 완료 버튼)

- GPS를 쓰지 않습니다. 지하 주차장에서 안 잡히고, 층·구역 텍스트가 더 정확합니다. **위치 권한이 아예 필요 없어** 로컬 전용 정체성과도 맞습니다.
- 입력·온고잉·자동 제거는 전부 표준 API라 리스크가 없습니다.
- **유일한 불확실성은 "연결 끊김"을 놓치지 않고 빨리 잡는 것**: 안드로이드 오토는 전용 API(`CarConnection`), 오토를 안 쓰면 블루투스 끊김 브로드캐스트인데 제조사·절전 모드에서 씹힐 수 있습니다. 감지가 5분 늦으면 이미 엘리베이터 안이라 가치가 사라집니다.
- **먼저 할 일**: 감지만 하루 스파이크 → 실차 2대(유선/무선 오토가 다를 수 있음)에서 확인 → 되면 나머지는 이틀.

## 하지 않기로 한 것

다시 꺼내지 않기 위해 이유와 함께 남깁니다.

| 안 하는 것 | 이유 |
|---|---|
| 연비 랭킹 · 전국 유가 | 서버/외부 API 필요 — 로그인 없는 정체성과 충돌 |
| 차량 건강 점수 | 자의적 공식 대신 팩트 요약으로 (원칙 3) |
| 리포트를 광고로 게이팅 | 방금 만든 차별점이자 반복 방문 화면이라 게이팅과 상극, 현 규모에선 광고 수익 ≈ 0 |
| 세차 전용 탭 | 안 쓰는 사용자에게 빈 탭이 생김 — 배너/카드 진입 유지 |
| 주기 자동 백업 | 백업 권유 다이얼로그(1.2.2)로 대체 — 저장 위치·보관 개수·실패 처리가 줄줄이 따라옴 |
